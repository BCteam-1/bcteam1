Business Central 2026 Release Wave 2: What Existing Customers Should Test First

Quick answer

After a Business Central release wave, test in a sandbox before the update reaches production. Check extensions and customizations first, then integrations, then the daily tasks of each role: finance, purchasing and IT. For 2026 release wave 2 (version 29), also review new AI agents and expense features and decide whether to use them. Confirm current details in Microsoft's release plan.

Updates arrive on a schedule you do not control, and a mistake in production costs more than a week in a sandbox. Business Central follows a six-month release cycle, with the 2026 second wave (version 29) starting to roll out from October 2026. Planned features and dates can change, so verify details in Microsoft's documentation. This plan tells you what to test, whatever the wave contains.

What is release wave 2 and how does it reach you?

It is the second major update of 2026 for Business Central, labeled version 29. Online customers receive updates through Microsoft's update process, with some control over timing in the administration center. Features arrive over several months.

What should you test first?

Test in this order, because earlier items can block later ones:

  1. Extensions and customizations. Do all installed extensions have versions that work with the new release? Ask each publisher.
  2. Integrations. Test every connection to other systems with realistic data.
  3. Standard processes. Post a sale, a purchase, a payment and a bank reconciliation.
  4. Reports. Run your key financial and operational reports and compare results.
  5. Permissions. Check that each role still has the access it needs, and no more.

What should each role test?

RoleTest
FinanceJournals, posting, bank reconciliation, month-end reports, approvals
PurchasingPurchase orders, receipts, invoice matching, vendor payments
SalesQuotes, orders, invoicing, customer statements
IT or administratorUsers, permissions, extensions, job queue, integrations

Which new features should you consider?

Microsoft's release plans for wave 2 describe AI agents, such as a Sales Order Agent and a Payables Agent, and native expense management, among other items. Decide which are relevant. Read the data and permission requirements before activating anything, and test with a pilot group. See our post on enabling Copilot for the admin steps.

How do you run the test?

Use a sandbox environment with a recent copy of production data. Write a short script for each role. Record results, issues and who fixed them. Sign off before production updates.

Have a rollback and communication plan. Tell users what is changing and when.

Taylor’s Take

Updates are routine only if you treat them that way. A test plan, a sandbox and a named owner turn each release into an afternoon of checking. Skip them and each release is a gamble.

Frequently Asked Questions

Can I postpone the update?

Online customers have some control over timing within Microsoft's rules. Check the administration center.

Do I need a sandbox?

Strongly recommended. It lets you test without affecting live data.

Who should test?

The people who do the work every day, not only IT.

What if an extension is not ready?

Contact the publisher and plan around it. Do not update production until you know.
